## 1. Тема и пользователь

Проект «Кривой CLI»: агент-ассистент для работы с консольным инструментом, документация которого местами неверна. Пользователь — оператор небольшого онлайн-магазина, работающий с вымышленным CLI `shopctl` (товары, заказы, клиенты): он ставит задачи в свободной форме («выгрузи все заказы клиента А за декабрь»), а агент выполняет их командами, проверяя свои догадки запуском команд, а не доверяя документации.

## 2. Что покажете на защите

Демо из 2–3 последовательных задач: на первой агент натыкается на заложенные расхождения между документацией и фактическим поведением CLI (флаг из доков не существует, список тихо обрезается до 10 строк, команда виснет на интерактивном подтверждении), разбирается и фиксирует выводы в шпаргалку; следующую аналогичную задачу решает сходу и за меньшее число шагов — покажу трейсы обоих прогонов и дифф шпаргалки между ними. Первая рабочая версия: CLI с заложенными расхождениями и синтетической базой, агент с инструментами `run_command`/`read_docs`, шпаргалка с курацией после задач, сравнение с агентом без памяти. За рамками: поддержка реальных CLI, retrieval-режим (DC-RS) и перенос шпаргалки на других агентов — только если останется время.

## 3. Как собираетесь это сделать

Python (uv) и LangGraph: стоковый `create_react_agent` плюс инструменты `run_command` (песочница: allowlist только на `shopctl`, закрытый stdin, таймаут, одноразовый рабочий каталог) и `read_docs`. Сам CLI `shopctl` (~10 подкоманд на click поверх SQLite) и его документация с 6–8 заложенными расхождениями пишу сам; данные полностью синтетические — сид-скрипт генерирует ~200 сущностей. Запуск: `uv run python run.py "задача" --mode dc-cu`; трейсы — в Langfuse, туда же пишутся версии шпаргалки по задачам.

## 4. Контекст и память

Внутри задачи агент помнит историю своих шагов (состояние цикла LangGraph); между задачами единственная память — шпаргалка: компактный (≤60 строк) набор проверенных фактов о CLI, который кураторский LLM-шаг после каждой задачи дописывает, исправляет и чистит. Хранится как файл с версионированием по задачам, перед каждой новой задачей текущая версия инжектится в промпт. Межзадачная память — не вспомогательная фича, а исследуемый механизм, ядро проекта.

## 5. Как проверите качество

Набор из ~30 задач (на защите — не менее 10), сгруппированных вокруг заложенных расхождений, с повторением одних и тех же расхождений в разных задачах; каждая задача = промпт + детерминированный чекер по финальному состоянию SQLite, ручной разметки нет. Сюита прогоняется на одном и том же агенте в двух конфигурациях — с шпаргалкой (DC-Cu) и без памяти (baseline), с общим лимитом ~12 вызовов CLI на задачу. Порог успеха: с шпаргалкой не менее 7 из 10 задач защиты (≥70% на полной сюите) при преимуществе над baseline не менее 20 п.п. на задачах, затрагивающих эти расхождения; измеряю success rate, число вызовов CLI и токены.

## 6. На что опираетесь

Основа — статья [Dynamic Cheatsheet: Test-Time Learning with Adaptive Memory](https://arxiv.org/abs/2504.07952) (arXiv:2504.07952) и [репозиторий авторов](https://github.com/suzgunmirac/dynamic-cheatsheet). Готовым беру метод (цикл «генерация + курация памяти» и набор бейслайнов BL / DC-∅ / FH / DR) и идеи промптов; сам реализую среду (CLI с недостоверной документацией), задачи с чекерами, агента и раннер экспериментов. Воспроизведение статьи: метод DC-Cu против варианта без него на одинаковых задачах одного агента, при успеваемости — полная сетка бейслайнов и перенос финальной шпаргалки свежему агенту.

## 7. Что пока неясно

Главный риск — калибровка сложности расхождений: слишком легкие — агент каждый раз раскрывает их заново и память ничего не дает, слишком жесткие — ноль успеха в обеих конфигурациях; планирую закрывать пилотными прогонами. Второе — качество доступной по курсу модели: в статье маленькие модели от памяти не выигрывали, нужен достаточно сильный генератор (обсудить лимиты API курса). Действия с данными: все команды работают только с синтетической SQLite в одноразовой песочнице; в интерактивном демо-режиме деструктивные операции (delete, refund, ship) требуют подтверждения пользователя, в экспериментальных прогонах выполняются автоматически ради воспроизводимости. Также уточню у преподавателя: статья используется и в проекте по разбору алертов, подходы различаются (контролируемая среда и сетка абляций против применения к инцидентам).
